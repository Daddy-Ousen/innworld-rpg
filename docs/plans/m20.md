# M20 — Touch controls (plan)

Date: 2026-10-05 · Cloud session · Status: waiting for the user's choices.
Roadmap: "Releases → Touch controls (on-screen pad, menu buttons), then an Android build".
ADR: 0032 (0030 stays reserved for M19, Book 7).

## Why now
- The browser build is live (Pages, itch.io). On a phone it loads, but nothing works: every command is a key.
- Android (ADR 0029) waits for the same work.

## What the code does today (root cause)
- There is no InputMap. About 10 scripts read raw keys: `physical_keycode == KEY_E`, and `world/main.gd`
  polls `Input.is_physical_key_pressed(KEY_W)` for held walking.
- So an on-screen button cannot "press" a command. A fake key event would work, but it is a hack: it ties the
  touch layer to key codes and blocks key remapping later.
- What already works on touch: Godot turns a tap into a left mouse click (`emulate_mouse_from_touch`, on by
  default). So menu Buttons, the System dialog, the Skill bar and "tap a tile in a fight" already work.
- What does not work on touch: walking, wait, every hotkey (E, F, I, Z, C, J, L, H, B, T, X, 1-9), Esc (open
  the pause menu, close every panel, cancel an armed Skill), right click (stop a walk), mouse hover (fight preview),
  PageUp/PageDown in text pages.

## Design
1. **M20.0 Input actions (no behaviour change).** Add named actions to `project.godot` `[input]`: `move_n/s/e/w`,
   `wait`, `use`, `eat`, `bag`, `sleep`, `sheet`, `journal`, `log`, `help`, `menu` (Esc), `cancel`, `block`, `throw`,
   `drop`, `skill_1` … `skill_9`, `page_up`, `page_down`, `console`. Each keeps today's keys (physical keycodes).
   Replace the key checks in `world/main.gd` and the panels with `event.is_action_pressed(...)` and
   `Input.is_action_pressed(...)`. The keyboard plays exactly as before.
2. **M20.1 Touch layer.** New `ui/touch_controls.tscn` + `ui/touch_controls.gd` (presentation only), a CanvasLayer
   in `world/main.tscn`:
   - a 4-way D-pad (bottom left) and a Wait button; hold = walk, like a held key;
   - action buttons (bottom right): Use, Menu, and a "more" fan for Bag, Eat, Sleep, Sheet, Journal, Log, Help,
     Block, Throw, Drop;
   - each button uses `Input.action_press` / `action_release`, so `main.gd` cannot tell touch from keys;
   - a Back (X) button on panels that close only by key today (journal, sheet, bag, text pages, slot list,
     options, interact menu); a Cancel button while a Skill is armed or a walk runs.
3. **When it shows.** Setting `touch_controls`: Auto / On / Off in the options menu, saved with the audio
   settings (`user://`, not `GameState`; no save version change). Auto = on when the device has a touch screen
   (`DisplayServer.is_touchscreen_available()`) or after the first screen touch; a key press does not hide it.
4. **Fight on touch.** There is no hover. A tap shows the plan (path, hit chance) as hover does now; a second
   tap on the same cell acts. A mouse click still acts at once.
5. **M20.2 Android build** (local session, not cloud: needs the Android SDK, JDK and a keystore on the user's PC).
   "Android" preset, landscape only, stretch `canvas_items` + `expand` on mobile too, `tools/release.ps1` builds an
   APK. Separate PR.

## Limits in the cloud
- No display and no phone: I cannot see or tap the layout. GUT tests drive the actions headless.
- Left open for the user: play on a phone (Pages build after the next release) and on a PC with a touch screen.

## Not in scope
- The debug console (needs a typing keyboard; developer tool).
- Gamepad support (the InputMap makes it cheap later: add joypad events to the same actions).
- Key remapping UI (also cheap later, same reason).
