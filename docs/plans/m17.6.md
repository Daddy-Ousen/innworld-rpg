# M17.6 Cover and position — plan

Status: APPROVED choices (2026-09-30), see "Answers". Numbers below already use them. Build in progress.
Branch: `claude/kind-feynman-y4x1mm` (cloud session). One PR at the end. Roadmap: `docs/ROADMAP.md` M17.6. Rules: ADR 0027, ADR 0022.

## Goal
Where you stand matters in a fight.
- Solid things give **cover** against ranged attacks.
- Walls **block sight**, so nobody shoots or casts through a house.
- Attacking from the side of a target **beats its cover**, and being boxed in costs you (**flanking**).
- Monsters follow the same rules and use cover too.

## Facts found in the code (read first)
- Moves are four-way (n, e, s, w). Melee means side by side (ADR 0027). `Combat._dist` is the king distance (used for range).
- Hit chance is `0.7 + 0.05 × (accuracy − evasion)`, clamped 0.1–0.95 (`Combat.hit_chance`). `Combat.player_hit_chance` is the one
  formula for the screen and the blow (`Combat._strike`), so a cover bonus put there reaches both.
- Ranged sources today: the player's throw (`Combat.throw_at`, and the strike Skill with `thrown`), foe `ranged` (goblin grunt,
  goblin chieftain, crypt lord, Goblin Lord archer and shaman), player spells `one` and `blast` (`Spells.why_not`, `_hit_monster`),
  NPC casters (`Spells.npc_pick`). Helpers, NPC fighters and brawlers hit in melee only.
- There is **no sight check anywhere**. A `line` spell stops at the first unwalkable tile (M17.5). ADR 0027 left sight "for M17.6".
- Blocking things already exist as data: tiles with `walk: false` (walls, houses, cliffs, trees, rocks, boulders, water, chasm) and
  objects with `solid: true` (`MapDb._solid`: table, counter, shelves, wagon, well, ...). Every solid object has a `kind`.
- The open fight maps already have natural cover: floodplains_south 7 trees, 3 rocks, 2 boulders; inn_hill 3 trees, 4 rocks,
  2 boulders; ruins_entrance 8 trees, 2 rocks, 3 boulders, cliffs and walls; esthelm_ruins 22 rocks and many walls.
  So **no new map props are needed** (map edits risk the stage lanes: M16.6 lesson).
- Cover needs **no saved state**. It comes from map data and positions. No save change, no migration.

## Design (proposed; the open choices below may change it)
### Cover levels (data)
`none`, `half`, `full`, `wall`.
- `data/tiles.json`: optional tile field `cover` (default `none`).
- Map objects: optional field `cover` (only on `solid` objects). Default by object kind from
  `rules.combat.tactical.cover.kinds` (so no map file needs an edit). A per-object `cover` overrides the kind.
- Proposed tiles: `city_wall`, `building*`, `brick_house*`, `plain_house*`, `ruin_wall`, `wood_wall`, `wood_window`,
  `snow_wall`, `cliff`, `stone_cliff` = `wall`. `tree`, `boulder` = `full`. `rock` = `half`. Water, chasm, floors: `none`.
- Proposed objects: `counter`, `table`, `chess_table`, `bench`, `bed`, `stove`, `hearth`, `brazier`, `woodpile`, `milestone`,
  `market_stall`, `well`, `notice_board`, `basin`, `tombstone`, `grave_cross`, `bee_nest`, `honeycomb` = `half`.
  `shelves`, `wagon`, `fruit_tree`, `dead_tree` = `full`. `stone_doors` = `wall`. Campfire, stairs: none.
- The numbers live in `rules.combat.tactical.cover`: `half`, `full`, `flank` and the `kinds` table.

### Sight
A straight line between two tile centres (fixed algorithm, same result every time). A `wall` tile strictly between blocks it.
`half` and `full` things do not block sight. Needed for: the player's throw, a foe's ranged shot, spells `one` and `blast`,
NPC casters. Not needed for melee, `around` spells or `line` spells.

### Cover on a target
For a ranged attack from tile A on a target at T: the **sides of T that face A** (the side along the larger gap; both sides when
the gaps are equal). The best cover level on the tiles next to T on those sides counts. `half` lowers the hit chance,
`full` and `wall` lower it more. Melee ignores cover (an adjacent attacker has no barrier between). A spell that always hits
(`hit: auto`) ignores cover but still needs sight. The shooter at an angle where T has no cover on the facing sides is **flanking**
the cover: it gets the full chance.

### Flanking, and monsters
See "Open choices" 3 and 4.

## Risks
- Sight can change the canon stage fights that were tuned without it. Mitigation: run the stage sims after step 2, tune only the data.
- Cover changes hit chances, so the hit numbers in ADR 0027 change a little for ranged fights. Melee-only fights are unchanged.
  M17.7 redoes the balance anyway.
- No display in the cloud: the overlay cannot be looked at. Tests check the overlay state. The user checks the look at home
  (`godot --path game`, then walk to a tree and fight a goblin).

## Open choices (asked in the session)
1. **Sight:** do walls, buildings, cliffs block ranged attacks and spells?
2. **Cover numbers:** hit chance lost against half and full cover.
3. **Flanking rule** on a four-way grid.
4. **How monsters use cover and position.**

## Answers (user, 2026-09-30)
1. **Sight:** yes. `wall` tiles (walls, houses, cliffs) block throws, shots and `one` / `blast` spells. Trees, boulders, rocks and
   low objects never block sight; they only give cover.
2. **Cover numbers:** half -15 points, full -30 points (`wall` counts as full when the shooter still sees the target).
3. **Flanking:** pincer bonus +15 points when a target has foes on two opposite sides. It works for everyone.
4. **Monsters:** a shooter moves to a covered tile (move cap allowing) and shoots from it. Melee monsters, when two side tiles
   are equally near, take the one opposite an ally. Both are tie-breaks. No retreat-to-cover (M17.7).

Rule 11 (schema): ADR 0022 approved "cover values on tiles and objects (M17.6)". This plan adds: tile field `cover`, object field
`cover`, and `rules.combat.tactical.cover` (numbers + `kinds`). All optional, so old data stays valid. No save change.
