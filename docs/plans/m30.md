# M30 — Voices and the Earther: plan

Status: M30.0 DONE (2026-10-18, ADR 0044 "M30.0": schema, bark rule, cast, tone). M30.1 DONE (2026-10-18). M30.2 DONE (2026-10-18). M30.3 DONE (2026-10-18). M30.4 DONE (2026-10-19). M30.5 next. Source: `docs/AUDIT_PLAYER_2026-10-17.md` findings 1 and 3.
The biggest gain for a book reader. One branch + PR per step.

## Goal
The main cast sounds like themselves (in our own words), talking to them gives more than one generic menu, the
player hears them on the map, Erin reacts to another Earther, and the player is someone (name, look, background).

## Today
- One menu for every NPC: Talk / Persuade / Comfort / Attack (`rules.npc.talk_actions`, `core/interact.gd:73`).
- A talk adds a band greeting ("%s nods at you.") and maybe one topic line (`core/talk_topics.gd`, 17 topics).
- Each canon NPC record already has a `summary` with traits (`canon/book<N>/npcs.json`). Nobody shows it.
- The player has no name, no look choice, no background (`core/player_state.gd`, save v21).

## Steps

### M30.0 Design [Opus · high] (user)
- Write the voice schema and the bark rule into ADR 0044 ("M30.0"). Proposed `data/voices.json`:
  ```
  "relc": {
    "confidence": "guess", "canon_ref": {...},
    "greet": {"stranger": [..], "acquaintance": [..], "friend": [..], "close friend": [..], "wary": [..]},
    "idle": [..],                                    // barks on the map, view only
    "lines": [{"flags": [..], "not_flags": [..], "days": [a, b], "text": ".."}],   // after events
    "options": [{"id": "spar", "label": "Ask Relc to spar", "action": "weapon_practice",
                 "context": {"npc": "relc"}, "flags": [..], "min_band": "acquaintance"}]
  }
  ```
- User picks: the first cast (proposal below), the tone rules (short lines, under about 15 words, no book quotes),
  and approves the schema (rule 11).
- Bark rule: a bubble over an NPC within 4 tiles, at most one per NPC per 20 game minutes, picked by a stable hash
  (day, NPC, minute bucket), never `gs.rng`, never changes state (ADR 0044).

### M30.1 Engine [Opus · medium]
- `core/voice.gd` (RefCounted): `greet(gs, db, npc)`, `line(gs, db, npc)` (flag lines first, then talk topics),
  `options(gs, db, npc)`, `bark(day, npc, minute, db)` (pure). Loads and validates `data/voices.json` in `DataDb`.
- `Interact.options` adds the NPC's own options before the generic rows; `Interact.perform` runs them as their
  `action` with the given context. Old saves and NPCs with no voice behave as today.
- View: speech bubble (label over the head, fades) in `world/view_markers.gd`; also used for NPC lines in fights later.
- Validator: `tools/validate_data.py` checks `voices.json` (ids, bands, actions exist). Python tests.
- Tests: `unit_voice` (new), `unit_interact`, `unit_standing`, `unit_talk_topics`, `unit_world_view`,
  `unit_play_loop`; `tools/tests`.

### M30.4 The Earther meeting [Opus · medium]
- First talk with Erin after the player has met her: a one-time option "Tell Erin you are from Earth". A text page
  of 4 – 6 short exchanges (own words), then `erin.knows_player_is_earther`, relationship +3, and an offer to work
  at the inn. Erin's later lines can mention Earth (food, games, songs).
- Other Earthers react once too: Ryoka (Celum start or when met), Rose, Imani, Joseph and the others in Book 7+.
- A hook on an existing event is not needed; this is player life, not canon. Check `sim_canon_book1` stays at drift 0.
- Tests: `unit_voice`, `unit_interact`, `sim_canon_book1`, a new `sim_earther_meeting`.

### M30.5 Who you are [Opus · high]
- New game: name (text field, default "Earther"), look (4 – 6 presets from existing LPC parts), Earth background
  (pick one of about 6: student, cook, nurse, athlete, office worker, gamer). A background gives a small start bias
  to one class pool and one Erin line. Ryoka never levels; the player is not Ryoka.
- Save v23 + migration (v22 went to M29.1; old saves: name "Earther", look "player", background none). Touch: the creation screen
  works with touch and the UI scale.
- Files: `ui/title_menu.*`, `core/player_state.gd`, `core/game_state.gd`, `core/save_migrations.gd`,
  `tools/build_sprites.py` (presets), `data/appearance.json`, `data/rules.json` (backgrounds; ask).
- Tests: `unit_player_identity` (new: creation, save v23, migration from v22), `unit_game_state`,
  `unit_save_slots`, `unit_play_loop` (title flow), `unit_touch_controls`, `unit_ui_scale`, `unit_art`,
  `unit_class_system`.

talk works once; a new game asks name, look and background; old saves load; the touched tests pass; the user
