# M20.3 — UI scale for phones (plan)

Session 2026-10-05 (cloud, branch `claude/whats-next-xpoe4w`). User pick: "1" (UI scale before the next release).

## Problem
On a phone in landscape, the browser build shows the 1152 × 648 layout on a screen about 68 mm tall.
A menu button (24 px) is about 2.5 mm tall and 16 px text is about 1.7 mm. That is too small to tap or read.
The touch pad (64 px buttons) is about 6.7 mm, which is good.

## What the renders show (Xvfb, 2400 × 1080, web stretch, scale 1 and 2)
- Scale 2: Options, pause menu, System dialog and HUD are readable; buttons are about 5 mm.
- Scale 2 also zooms the map 2× (Camera2D sits in the same canvas): only a few tiles show.
- Scale 2 doubles the touch pad (about 13 mm buttons; the pad fills half the height).
- Journal (600 × 600) and Character sheet (560 × 400) do not fit a 324 px tall view: they run off the screen.
  Bag (480 × 360) and TextPage (560 × 400) have the same fixed sizes. All of them already scroll inside.

## Design
- **One knob:** `Window.content_scale_factor` on the root window. Godot multiplies every Control by it,
  in all stretch modes (desktop "disabled" and web "canvas_items"). No theme or font change.
- **`ui/ui_scale.gd` (`UiScale`, RefCounted, pure):** mode `auto`, `1`, `1.5`, `2`; saved in
  `user://settings.cfg` (section `display`, key `ui_scale`) like `TextSettings`. Not `GameState`: no save change.
  `static auto_factor(short_px, dpi, touch) -> float`: 2 when the device has a touch screen and the short side
  of the window is under 5 "inches" (`short_px / dpi`), else 1. On the web `dpi` is 96 × devicePixelRatio, so a
  phone reads about 4 in, a tablet 8 in, a PC 7 – 11 in. Without a touch screen Auto is always 1, so a small
  desktop window never jumps to 2.
- **`Session`:** loads it, applies the factor, and applies again on window resize (phone rotate, browser resize).
  Signal `ui_scale_changed`.
- **Map:** the world camera zoom becomes `2 / factor`, so the map keeps its size (open choice 1).
- **Touch pad:** its sizes are divided by the factor, so the pad keeps its size (open choice 2).
- **Panels fit:** a small static helper clamps a centred panel to the view (design size, but at most the view
  minus a margin). Journal, Character sheet, Bag, TextPage call it when they open and on resize.
  The Journal focus list (min height 170) gets less height on a small view.
- **Options:** a row "Menu size": Auto / 100% / 150% / 200%.
